# Production on Google Cloud: the three branches together (ADR-0098)

Branch `integration/google-cloud`: main (after batch 2, #163) plus, in order,
`docs/production-google-cloud`, `feat/api-google-cloud-adapters` and `feat/infra-google-cloud`.

## What changed

- Merged the documents, the API's adapters and the Terraform for Google Cloud europe-west2. Each
  merge commit lists the conflicts it resolved by hand: records of processing, the ADR index,
  STATUS, human actions and the infra README (docs); `apps/api/package.json`, the lockfile and
  `config.ts` (adapters); the infra README and the stack's `services.tf` (infra). The hazard log
  merged without a conflict. OpenAPI and the typed client were regenerated, not hand-merged.
- Batch 2 code that still used AWS:
  - Single sign-on keys (ADR-0091) were read from AWS Secrets Manager (`@aws-sdk/client-secrets-manager`).
    They are now regional Secret Manager secrets in europe-west2, read through the regional
    endpoint with the runtime's identity (`SecretManagerKeyStore`, `google-auth-library`, already
    in the tree through `@google-cloud/storage`). The store name `harbour/sso/<tenant>/<name>` maps
    to the secret id `harbour_sso_<tenant>_<name>`. Existence is checked from the latest version's
    metadata, never by reading the key; a key the API may not read counts as missing.
    `SSO_KEY_STORE` is `gcp` or `memory`, and production needs `gcp`.
  - The speak-up throttle secret (ADR-0089), which the API refuses to start without, is now a
    Secret Manager secret in the Terraform (`api-speak-up-throttle-secret`), generated by
    `seed-secrets.sh` and read by the API and worker; the stack sets `SSO_KEY_STORE=gcp`. The plan
    test checks both.
  - Disclosure packs already go through the storage port into the exports bucket, and the merged
    key pattern accepts them, so they land in Cloud Storage under the bucket's key.
- ADR-0098 amended to what was built: downloads stream through the API (no signed URLs),
  quarantine is a document status rather than a bucket, and there is no Cloud KMS adapter yet
  (per-organisation crypto-shredding is on `feat/platform-crypto-shred`). ADR-0031 and ADR-0091
  carry notes, and the hazard log, safety case v0.2, records of processing, retention and
  deletion, the platform, export and safety specs, the on-call runbook, H-08 and H-751 say the
  same.
- `.env.example` gains the storage (`DOCUMENT_STORAGE`, `GCP_PROJECT_ID`, `GCS_*`), SMTP (`SMTP_*`)
  and SSO key store settings, and names Secret Manager.
- STATUS: the Google Cloud entry says what is merged and what is left; the header lines a
  previous merge left doubled are one again, with the register's current counts.
